# Milestone 3 findings (2026-10-31)

rclone v1.75.2 (official binary), Ubuntu 26.04.1, fuse3 3.18.2.

- The rclone **snap cannot mount**: `mount/mount` answers "mounting is not supported when running from snap". Its
  private `/tmp` also hides files from the host. Development and CI use the official binary (`NUAGE_RCLONE`).
- Credentials for rcd go through `RCLONE_RC_USER` / `RCLONE_RC_PASS`, so they never appear in `ps`.
- `mount/mount` accepts `CacheMaxSize` as a byte count and `CacheMaxAge` / `WriteBack` as duration strings
  (`"2592000s"`, `"8760h"`); `vfs/stats` echoes them (`CacheMaxSize:20Gi`, `WriteBack:1y`).
- An `alias` remote is cached under the wrapped path (`vfs/local/<path>`), not `vfs/<remote>`; two aliases of the same
  folder share one VFS and one upload queue. The engine deletes the cache paths reported by `vfs/stats`.
- `vfs/queue` item after a write with `WriteBack=8760h`: `{"delay":31536000,"expiry":31535998.4,"uploading":false}`;
  `vfs/queue-set-expiry` with `-1e9` uploads it within a second. Confirmed end to end, including across a daemon
  restart (the held write is queued again at the next mount).
- Unix socket paths are limited to 107 bytes; `nuaged` now says so instead of failing on a "stale socket".
- An rcd left by a daemon killed with `SIGKILL` keeps serving its mounts; the next daemon stops it through
  `data/rcd.pid` (checking `/proc/<pid>/cmdline` first), then detaches what remains.
