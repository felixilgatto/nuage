# Milestone 5 findings (2026-11-01)

rclone v1.75.2, Ubuntu 26.04.1 (GNOME 50, gnome-keyring), a real Google account with a personal "Desktop app" client
published in Production.

## Sign-in through rc

- `config/create` (drive, `nonInteractive`) with `config_auth_no_browser=true` stops at `config_is_local` (state
  `*oauth-islocal,teamdrive,oauth,`). `config/update` with `continue`, `result: "true"` and `_async: true` starts
  rclone's OAuth server; `config/oauthstatus` returns `{"status":"running","authUrl":"http://127.0.0.1:53682/auth?state=…"}`
  and the page redirects (307) to `accounts.google.com` with the client and `redirect_uri=http://127.0.0.1:53682/`.
- After the code, rclone asks `config_change_team_drive` again: answers given to `config/create` are **not** kept for
  the following steps. Nuage answers such questions from the provider's `config_*` parameters.
- `config/oauthstop` cancels; the job then fails with "oauth authentication was cancelled".
- Reconnect: `config/update` with `config_refresh_token=true` leads to the same `config_is_local` question.
  `config/get` returns `client_id` and `client_secret` in clear (they are not rclone "password" options), so a second
  account reuses the client of the first one.
- End to end with a real account: sign-in in about 5 s, account mounted, quota reported (`operations/about`, trash
  included).

## Secrets

- `rclone config encryption set --password-command "printenv NUAGE_RCLONE_CONFIG_PASS"` encrypts a plain file
  without a terminal; an `rcd` started with `RCLONE_CONFIG_PASS` reads and writes it encrypted; a wrong password stops
  rclone at startup ("unable to decrypt configuration").
- `oo7` (Secret Service natively, Secret portal in the Flatpak) created and read the password on the desktop. The
  Flatpak path is not tested yet (milestone 11).

## Google Docs

- `export_formats=link.html` gives `<name>.link.html`, a page with a `meta refresh` to the document.
- **Opening**: Files opens it with the default `text/html` application, which is **Thunderbird** on the test machine.
  Nuage cannot intercept a double-click in Files; the README explains how to make the browser the default. Nuage's own
  browser (milestone 9) will open documents with the default `https` handler.
