# Milestone 1 findings (2026-10-30)

Host: Ubuntu 26.04.1, fuse3 3.18.2, Flatpak 1.16.6, GNOME runtime 51, rclone v1.75.2.

## FUSE from the Flatpak sandbox

- The GNOME Builder / RClone Manager wrapper (`flatpak-spawn --host --forward-fd=$_FUSE_COMMFD fusermount3`) **fails on Ubuntu 26.04**:
  `fusermount3: file descriptor 3 is not a socket, can't send fuse fd`.
- Cause: `/etc/apparmor.d/fusermount3` has no `unix` rule, so an inherited socket from a confined peer is denied:
  `apparmor="DENIED" operation="file_inherit" class="net" profile="fusermount3" ... peer="unpriv_bwrap"`.
  `flatpak-spawn --forward-fd` itself is fine (the host process sees a socket on the same fd number).
- Workaround (validated): a host-side relay creates its own socketpair, runs `fusermount3` with it, receives the `/dev/fuse`
  fd via `SCM_RIGHTS` and sends it back over the sandbox's socket. Prototype in `poc/flatpak-fuse/fusermount-wrapper.sh`
  (Python relay run with the host's `python3`). Mount, host read, host write (uploaded to the source), and unmount through
  the wrapper all work. Remaining AppArmor denials (`dac_override`, `setuid`) are the known harmless ones (LP: #2122161).
- `$XDG_RUNTIME_DIR/app/$FLATPAK_ID/` is shared with the host at `/run/user/$UID/app/<app-id>/`: a host CLI can reach a
  socket created there by the sandboxed daemon.
- flatpak-builder (Flatpak app) needs `--disable-rofiles-fuse` here, and its state/build dirs must live under `$HOME`.

## Prior art: RClone Manager

- Manifest has neither `--talk-name=org.freedesktop.Flatpak` nor `--filesystem=home`; users must `flatpak override`
  (issues #45, #52, #113).
- rclone is not bundled: the latest release is downloaded at runtime (no pinning).
- Shows quota (`operations/about`), no "up to date / syncing" state (does not read `vfs/stats`).

## rclone rc (v1.75.2)

- `mount/mount` accepts `{"fs","mountPoint","vfsOpt":{CacheMode,CacheMaxSize,CacheMaxAge,WriteBack},"_filter":{ExcludeRule,FilterRule}}`.
  Filters hide excluded remote entries and make them unreadable, but **a new local file matching an exclusion is
  accepted and uploaded**. `rclone rc` cannot mix `--json` with `key=value` args.
- `vfs/stats` requires `fs` when more than one VFS is active. `diskCache` keys: `bytesUsed, erroredFiles, files,
  hashType, outOfSpace, path, pathMeta, uploadsInProgress, uploadsQueued`. `bytesUsed` updates only on the cache poll (60s).
- `vfs/queue` → `{"queue":[{name,id,size,expiry,tries,delay,uploading}]}`.
- Pause: `vfs/queue-set-expiry {"fs","id","expiry":1e9}` holds an item, `-1e9` releases it; rewriting a held file resets
  its delay to `WriteBack`. `core/bwlimit` is global and never fully pauses. Pending writes survive `core/quit` and are
  re-queued on remount with the new `WriteBack`. Chosen design: very long `WriteBack`, the daemon releases items when not paused.
- Drive link export formats: `desktop`, `link.html`, `url`, `webloc`; link files are read-only. Nautilus 50 opens
  `.desktop` in Text Editor; `link.html` opens with the default `text/html` handler. Default export is `docx,xlsx,pptx,svg`.
- Drive OAuth: rclone's shared client ID "will stop working during 2026" (state `client_id_warning`).
  `--auth-no-open-browser` exists only for `rclone authorize`; with `config/create` use `config_auth_no_browser`.
  Non-interactive state machine: `config/create` with `opt:{nonInteractive:true,obscure:true}`, then `config/update`
  with `opt:{nonInteractive,continue:true,state,result}` until `State` is empty. One-shot: pass `token`,
  `config_refresh_token:"false"`, `config_change_team_drive:"false"` in `parameters`. `config/create` saves the remote
  before the questions end (delete on abort). Desktop flow: `_async` + `config/oauthstatus` (`authUrl`) / `config/oauthstop`.
- `operations/about` (local) → `{free,total,used}`, missing fields omitted; `memory` backend returns 500 (check
  `Features.About`). `operations/fsinfo` → `{Features,Hashes,MetadataInfo,Name,Precision,Root,String}`.
